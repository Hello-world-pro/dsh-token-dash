### 0.5.1 ProgressRing（进度环）

> 使用范围：P1 的预算与订阅窗口、P2 的订阅窗口都用它；P3 需要时同样复用，不另写实现。

| 项 | 规格 |
|---|---|
| 职责 | 纯展示：按百分比画描边环；**不自算阈值、不含业务文案** |
| Props | `percent`（0–100）、`state`（`normal` / `critical` / `empty`）、`size=14`、`stroke=2`；实际取值 P1 用 14 / 2、P2 用 20 / 2.5 |
| 几何 | `viewBox="0 0 14 14"`、`r = (size - stroke) / 2`、`strokeDasharray = C * percent / 100 + " " + C`、`transform="rotate(-90 7 7)"`、`strokeLinecap="round"` |
| 形态 | **描边 donut，中间透明**；草图的 `◔` 仅示意填充，落地不是实心饼 |
| 颜色 | 轨道 `--dsw-alias-border-l3`；弧 `critical → --dsw-alias-state-error-primary`，其余 `--dsw-alias-label-primary`（暗色≈白 / 亮色≈黑）；`empty` 不画弧 |
| 主题 | 只用语义 token；组件内零 hex、零 `@media (prefers-color-scheme)` 分支，明暗由宿主切换 |
| 无障碍 | 作装饰时 `aria-hidden`，数值由相邻文本承担；独立使用时 `role="progressbar"` + `aria-valuenow/min/max` |
| 阈值 | 调用方算：订阅 `≥90` → `critical`；API 预算 `≥100` → `critical`（80–100 只染数字，不染环） |

```jsx
function ProgressRing({ percent, state = 'normal', size = 14, stroke = 2 }) {
  const r = (size - stroke) / 2
  const c = 2 * Math.PI * r
  const arc = state === 'critical' ? 'var(--dsw-alias-state-error-primary)' : 'var(--dsw-alias-label-primary)'
  return h('svg', { viewBox: `0 0 ${size} ${size}`, width: size, height: size, 'aria-hidden': true },
    h('circle', { cx: size / 2, cy: size / 2, r, fill: 'none', stroke: 'var(--dsw-alias-border-l3)', strokeWidth: stroke }),
    state === 'empty' ? null : h('circle', {
      cx: size / 2, cy: size / 2, r, fill: 'none', stroke: arc, strokeWidth: stroke, strokeLinecap: 'round',
      transform: `rotate(-90 ${size / 2} ${size / 2})`,
      strokeDasharray: `${c * Math.min(100, Math.max(0, percent)) / 100} ${c}`,
    }))
}
```

### 0.5.2 ResetClock（重置时间，P0）

> 现有实现散在 `client.js` 的 `fmtReset`（131-143）与 `ResetLabel`（790-795）：前者拼成一整句 `3 小时后 · 11-03 20:15`，后者再补「重置」二字。P2 需要把「倒计时」和「绝对时间」拆成两段分别排版，因此抽成组件。

| 项 | 规格 |
|---|---|
| 职责 | 把重置时间戳格式化成两段文本：`relative`（倒计时）与 `absolute`（绝对时间）；不负责取数、不负责配色 |
| Props | `ts`（毫秒时间戳）、`now`（可选，默认 `Date.now()`，便于测试注入） |
| 输出 | `{ relative, absolute }`；`ts` 非有限值或 ≤0 时两者均为 `null` |
| 相对时间 | `<60 分钟` → `{n} 分钟后`（最小 1、四舍五入）；`<1440 分钟` → `{n} 小时后`；否则 `{n} 天后` |
| 绝对时间 | `MM-DD HH:mm`，月/日/时/分补零，本地时区 |
| i18n | 复用现有词条 `{n} 分钟后` / `{n} 小时后` / `{n} 天后`；绝对时间为数字，不翻译 |
| 渲染 | 默认返回 `relative · absolute` 一行；需要分段排版时由调用方取字段自行摆放 |
| 复用 | P2 订阅行（两段分别占列）；P3 订阅表（只用 `absolute`，保持表格列）；P1 不使用（已定不显示重置） |

```jsx
function resetParts(ts, now = Date.now()) {
  if (!Number.isFinite(ts) || ts <= 0) return { relative: null, absolute: null }
  const date = new Date(ts)
  const pad = (v) => String(v).padStart(2, '0')
  const absolute = `${pad(date.getMonth() + 1)}-${pad(date.getDate())} ${pad(date.getHours())}:${pad(date.getMinutes())}`
  const minutes = Math.max(1, Math.round((ts - now) / 60000))
  const relative = minutes < 60 ? tr('{n} 分钟后', { n: minutes })
    : minutes < 1440 ? tr('{n} 小时后', { n: Math.round(minutes / 60) })
      : tr('{n} 天后', { n: Math.round(minutes / 1440) })
  return { relative, absolute }
}
```

### 0.5.3 TokenTable（用量表，P0）

> 使用范围：P2 的模型用量表；P3 明细表沿用同一套列与对齐规则（P3 多一列费用）。**列宽全部自适应**，不写死像素。

| 项 | 规格 |
|---|---|
| 职责 | 渲染模型级用量行；只管排版与格式化，不含取数与排序策略 |
| Props | `rows`（`model / total / input / cache / output / requests / hitRate`）、`maxRows=5`、`empty` |
| 列模板 | `grid-template-columns: minmax(0,1fr) auto auto auto`（模型 / Tokens / 请求 / 命中）；**除模型列外全部按内容自适应** |
| Tokens 单元格 | 两段 flex：左段「总量 + 单位」`flex:1; text-align:right`，右段 `[输入/缓存/输出]` `flex:none; text-align:left`；两段间距 4px |
| 对齐基线 | 以**「单位」与 `[` 的交界**为对齐线：所有行的 `[` 左缘落在同一竖线上，数字右缘贴齐该线；不整格居中、不左对齐 |
| 单位 | 复用现有 `fmtTokens`（`client.js:111-118`）：`<1000` 整数、`<1e6` `k`、`<1e9` `M`、否则 `B`；保留 1 位小数并去掉 `.0` |
| 列对齐 | 模型左对齐，Tokens / 请求 / 命中右对齐；表头与数据同列同向，不居中 |
| 行数 | 最多 5 行，超出表格内部滚动；行距 6px，无表头分隔线 |
| 空态 | `范围内暂无消耗`，不渲染表头 |
| 费用 | **不包含费用列**；P3 需要时在末尾追加一列 `auto`，边界规则不变 |

```jsx
// 关键：两段共用一条对齐基线，多行/多列都不会错位
h('span', { style: { display: 'flex', alignItems: 'baseline', gap: 4, minWidth: 0 } },
  h('span', { style: { flex: 1, textAlign: 'right' } }, fmtTokens(total)),
  h('span', { style: { flex: 'none', color: T.weak, fontSize: 'var(--td-fs-micro, 12px)' } },
    `[${fmtTokens(input)}/${fmtTokens(cache)}/${fmtTokens(output)}]`))
```

### 0.6.5 数字规则

| 规则 | 说明 |
|---|---|
| 对齐 | 所有数字 `font-variant-numeric: tabular-nums`，避免刷新时跳动 |

| 百分比 | 1 位小数去尾 `.0`（`25%`、`42.5%`）；不补 `100.0%` |
| 金额 | 币种符号紧贴数值（`¥12.68`）；`/` 两侧各 1 个空格（`¥12.68 / ¥50.00`） |

| 禁止 | 不写死 `px` 字号、不用 `opacity` 模拟弱化、不用等宽字体族 |

### 2.2 规格

| 项 | 规格 |
|---|---|
| 宽度 | **自适应内容，不做固定宽**：`width: fit-content`，由最宽的一行决定；`min-width: 280px`、`max-width: min(480px, calc(100vw - 16px))`；E2E 断言由 `width ≈ 360` 改为 `280 ≤ width ≤ 480`；实测 `fit-content` 在 1280 视口下为 **311.8px**，说明自适应生效 |
| 高度 | `max-height: max(200px, min(70vh, pillTop - 16px))`；贴 pill 上方 8px |
| 宽度上限行为 | 触到 `max-width` 后：模型名列按 `minmax(0,1fr)` 截断（省略号），数字列仍完整；不出现横向滚动 |
| 宽度过渡 | 切换 provider / 切换范围导致宽度变化时，`transition: width 120ms ease-out`；`ResizeObserver` 触发重新定位，避免面板跳动或超出视口 |
| 定位 | 宽度变化后重算左右翻转与 `panelShift`，右缘不足时向左展开 |
| 头部 | 标题「当前模型」左对齐 + `ⓘ` / `⟳` / `×` 三个 22×22 按钮；**按钮组右对齐到内容右缘**，与 provider chip、最后一列共用同一条竖线；**不再有「用量 / 设置」双 tab** |
| 头部对齐偏差 | 按钮为 22×22、图标居中时右侧会多出约 5px 空白；用 `margin-inline-end: -5px` 抵消，让**图标视觉右缘**与下方数字右缘齐平 |
| provider 顶行 | `display:flex; justify-content:space-between`：provider 名左对齐，`[按量 API]` / `[订阅]` chip **右对齐到内容右缘**，与下方最后一列（余额 / 绝对时间）落在同一条竖线上 |
| 字号 | 正文与数字 `--td-fs-body`（13px）、括号 `--td-fs-micro`（12px）；标题同 13px、靠 600 字重区分；详见 §0.6.3 |
| 主区 · API | **一行四列**：`环 + 百分比`（auto）+ `已用/预算`（1fr）+ `真实余额`（1fr）+ `本月已花`（1fr）；**不渲染进度条** |
| 列分布 | `grid-template-columns: auto 1fr 1fr 1fr; column-gap: 8px`；环区按内容宽，右侧三块**均分剩余宽度**，每列左对齐 |
| 列内容 | 全部用 `--td-fs-body`（13px）：① `◔ 25%`：环 20px + 百分比 600；② `¥12.68 / ¥50.00`：400 + `label-tertiary`，不写标签；③ `真实余额 ¥8.74`；④ `本月已花 ¥12.68`（标签 400 tertiary、数值 600 primary）。两者都用 `title` 说明：余额=「账户真实余额，不受预算影响」，已花=「本月累计消耗，等于已用/预算 的分子」 |
| 溢出降级 | 单列不足时先压缩币种符号与 `/` 两侧空格；**可用宽度** <320px（窄视口撑满时）仍放不下，则末列整体换到第二行（沿用同一 grid），不截断金额、不缩字号；订阅行同理，倒计时与绝对时间一同换行 |
| 主区 · 订阅 | 每个窗口**一行四列**：`标签 + ProgressRing(20) + 百分比`（auto）+ `剩余 N%`（1fr）+ 倒计时（1fr）+ 绝对时间（1fr）；后三段**均分剩余宽度**、各自左对齐 |
| 订阅列内容 | ② `剩余 58%`：`100 - 已用`，取整、不带小数；③ `3 小时后`：来自 §0.5.2 `resetParts().relative`；④ `11-03 20:15`：`resetParts().absolute`；缺失窗口三段都显示 `—` |

| 底部 | 左「更新于 HH:mm」（12px tertiary）；右为**纯文字按钮「全量看板」**（12px、高 22、padding 0 8、圆角 6），点击跳 P3（跳转能力待验证） |
| 底部按钮样式 | 复用现有蓝色按钮：文字 `var(--td-accent)`；背景 `color-mix(in srgb, var(--td-accent) 16%, transparent)`；边框 `32%`；hover 背景 24% / 边框 48%；active 28% / 64%；focus 走宿主 focus ring |

```text
   ├─ section 数据区     正常流（按量计价 / 订阅套餐 / 范围 / 两格卡 / 明细）
   └─ section 设置与数据管理        ← 最后一段
      └─ capsule        position: sticky; bottom: 12px; z-index: 2
                        ↑ 粘在滚动容器底部，不是 window 视口
```

| 项 | 规则 |
|---|---|
| 锚定对象 | **宿主中栏滚动容器**（实测 `.mP3x-q_centerCol`，`overflow: hidden`、`scrollHeight 1389 / clientHeight 900`），不是 `window`；页面本身不产生第二层滚动 |
| 容器前提 | **父级必须真的可滚动**（`scrollHeight > clientHeight`）。实测宿主中栏就是 `overflow: hidden` 的滚动容器，`sticky` 仍然生效——所以「不能 overflow hidden」这条判断是错的，已删 |
| 距离 | `bottom: 12px`；移动端 `bottom: calc(12px + env(safe-area-inset-bottom))` |
| 底部留白 | 页面末尾 `padding-bottom: 96px`（≈ 胶囊高 + 24），避免最后一行内容被盖住 |
| 层级 | `z-index: 2`：高于表格表头、低于任何浮层 / tooltip |
| 退化条件 | 满足任一即改 `position: static`：① 视口高 < 480px；② 胶囊展开高度 > 40vh；③ 宽度 < 760px（窄屏换行后不再吸底） |
| 滚动行为 | 滚动容器加 `overscroll-behavior: contain`，胶囊内滚到底不带动整页 |
| 焦点 | 键盘 Tab 进入胶囊时 `scroll-margin-block: 12px`，避免焦点元素被胶囊自身遮挡 |
| 遮挡检查 | 明细表最后一行、胶囊、页面底部三者之间必须留 ≥ 24px，走查时以“滚到底”状态验收 |

### 3.6 空态与窄屏

**区块按计费类型分流（空态按区块独立判断）**

| 情况 | 表现 |
|---|---|
| 只有 API、没有订阅 | 隐藏「订阅套餐（按供应商）」整块（含标题），不留空表 |
| 只有订阅、没有 API | 隐藏「按量计价（按供应商）」整块（含标题） |
| 两类都没有 | 顶部单个空态卡（见下），其余数据区不渲染 |
| 某一类全部探测失败 | 该区块保留表头 + 每行显示失败原因，不整块隐藏 |

**两类都没有时（空态卡）**

```text
未检测到已配置供应商
  DeepSeek   未配置 Key
  智谱 AI    请求失败
  Kimi       已隐藏
[ 重新检测 ]
```

**窄屏（< 760px）**

```text
按量计价表退化为两行卡片（只对 API 行生效）：
  DeepSeek   月度预算 ¥50.00 ✎        已用 ◔ 25%

```

| 状态 | 表现 |
|---|---|
